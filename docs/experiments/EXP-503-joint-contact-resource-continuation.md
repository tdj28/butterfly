# EXP-503: resource-only continuation of the EXP-502 matrix

Prospective recovery design written while EXP-502 is still running. The first
fixed point's raw audit has been inspected: it qualifies but is not a joint
contact. Two completed points each require about 1.2 GiB; their sizes, not
their scientific outcomes, motivate this preparation. EXP-502's 8 GiB output
cap is unchanged and its attempt marker must never be reset. If that run
finishes within its cap, this recovery is unnecessary and must not execute.

## Exact reuse and remaining computation

Execution requires an archived EXP-502 `BudgetStop` failure, its source/input
binding, and a contiguous prefix of at least six completed fixed stencil
slots. Reuse **every** completed slot, irrespective of its qualification or
contact result. Hash the entire failed-run inventory, including partial raw
files. The interrupted slot remains a failed partial attempt and is computed
once anew in a separate directory; no partial profile is silently spliced
into a completed point. No original evidence is deleted or overwritten.

The numerical plan, original cold seeds, eight parameter specifications,
representations, solvers, precision profiles, correspondence guards, 256
response variants, two scales, conditioning gates, one radially clipped
proposal, and scientific success/failure definitions are **exactly EXP-502**.
Use its unchanged `evaluate`, response and per-point raw audit functions.
Every remaining stencil point runs regardless of prior scientific failures.
Reconstruct the response from the entire completed matrix. At most one
proposal parameter value is allowed; if a resource-interrupted proposal
already exists, its fresh attempt must use that same value and original
seeds. Previously completed proposal evidence is reused, never repeated.

The combined result is EXP-503, with mixed execution provenance explicitly
reported. It is not a retroactive successful EXP-502 run, an independent
replication, or repaired evidence for earlier scientific failures. All 26
inherited ledger entries remain. Raw replay, not the compact JSON alone,
supports trajectory validation. Jones words, C/D and chain arrows remain
unverified regardless of residual reduction.

## Resource amendment and accounting

Only operational limits change: at most 4 GiB of **additional** output,
7,200 seconds for this continuation, 9 GiB free before launch and a 6 GiB
free-space floor. The smaller reserve is explicit and prospective; no
scientific accuracy threshold is loosened. The original output remains
read-only. This allows completing the same small matrix without deleting
research evidence or uploading it elsewhere. If these limits are still
insufficient, retain another explicit resource failure; do not extend them
silently. No API calls, rentals, credentials or new uploads are involved.

The original failure counter is retained as **reserved integration attempts**,
not automatically relabeled an exact count of completed calls: the original
budget callback can increment immediately before a storage check rejects
launch. Completed-point counts are reconstructed exactly from archived raw
products plus guard meshes. The successor checks all limits before incrementing
its own call counter. Keep the original partial-attempt reservation count
separate from the exact completed-matrix trajectory count. The combined
reservation cap is 4,096; this resource amendment does not erase failed work.

## Pre-execution validation

Freeze this resource protocol, the checkpoint consumer, source closure,
failure/raw hashes, tests and auditor before computing remaining targets.
Require a clean live-pushed source revision and isolated copied-source startup
against the authentic hash-bound original failure as read-only data. Unit
tests use outcome-free checkpoint fixtures. The completed EXP-502 analytic
control artifacts are hash-bound and replay-audited, not regenerated merely
to perform a resource continuation. A synthetic control tests contiguous
prefix reuse, forbidden favorable-subset selection, preservation of an
interrupted slot, and exact remaining slot/proposal selection.

Full post-run audit checks original source bindings, the archived failure and
complete raw inventory, every reused and new point through the unchanged
per-point auditor, and the complete reconstructed joint proposal and verdict.
It reports separately what raw information exists for incomplete attempts.
This is a local audit with shared numerical/classification code, not paid
Pro review or independent-team replication.
